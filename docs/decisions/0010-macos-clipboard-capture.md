# 0010 — macOS clipboard capture: change-count polling, concealed data never read

Status: accepted

**Decision.**

- A `Timer` on the main run loop (common modes) reads `NSPasteboard.general.changeCount` every 0.3 s. Nothing else is touched until the count moves.
- On a change the main thread copies out one kind of content, in the order files, text, image. Concealed data is never read. Decoding, thumbnails, file sizes and the database write run off the main thread, one change at a time so history keeps copy order.
- Concealed means the pasteboard carries any of `org.nspasteboard.ConcealedType`, `org.nspasteboard.TransientType`, `org.nspasteboard.AutoGeneratedType`, `com.agilebits.onepassword` or `de.petermaurer.TransientPasteboardType`.
- The source app is the frontmost application at the moment the change is noticed, by bundle identifier.
- The ignore list is the built-in password managers plus the `ignoredApps` array in `UserDefaults` (edited in the Settings window, step 2.5). The app gives it to the core with `set_rules` each time the history opens; if that fails, nothing is captured.
- The watcher asks the app before reading data. Private mode and ignored apps are dropped there, by the settings as saved, and the core applies the same rules again in `record`. If the change count moved while the data was read, the read is dropped and the next poll takes the newer copy (decision 0026).
- Limits before the core sees an item: at most 1000 files per copy, at most 100 million pixels per image, and nothing larger than the core's `max_item_bytes`. Thumbnails are PNGs up to 256 px.
- What is on the pasteboard when the watcher starts is not captured.

**Why.**

- macOS has no clipboard change event; polling the change count is the standard way and costs almost nothing while idle.
- Not reading concealed data keeps secrets out of Clipo's memory, not just out of the database.
- The pasteboard does not say which app wrote to it. The frontmost app is right in practice, and the ignore list is a second line behind the concealed markers.
- The content on the pasteboard at launch may come from an ignored app; only a new copy lets us tell.

**Consequences.**

- A copy followed by an app switch within 0.3 s is credited to the wrong app, so an ignored app's copy can slip into history in that case. Concealed markers are the real protection for password managers.
- Clipboard changes made faster than 0.3 s apart collapse into the last one.
- The default ignore list is best effort; bundle identifiers can change between app versions.

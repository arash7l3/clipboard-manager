# 0032 — Windows: the popup leaves the focus where the user types, and picked images paste into folders

Status: accepted. Supersedes the focus part of decision 0016 and the Windows part of decision 0031. Windows only; the macOS app is unchanged.

**Decision.**
- **The popup is never activated.** It is a `WS_EX_NOACTIVATE` window shown with `AppWindow.Show(activateWindow: false)` and put at the top of the always-on-top windows without activation; its window procedure answers `WM_MOUSEACTIVATE` with `MA_NOACTIVATE`. The app the user was typing in stays the active window and its field keeps the keyboard focus, caret and selection, as on macOS (decision 0011). Should Windows ever bring the popup to the front anyway, Clipo hands the front straight back.
- **Keys.** While the popup is open, a low-level keyboard hook (`PopupInput`) catches the popup's keys on their way to that app and keeps them from it. `PopupKeys` decides which: typing (read with the keyboard layout of the app in front, AltGr included, and characters sent as `VK_PACKET`), Backspace, Ctrl+Backspace, Up, Down, Page Up, Page Down, Home, End, Tab, Shift+Tab, Enter, Shift+Enter, Esc, Ctrl+1 to Ctrl+9, Ctrl+P and the shortcut itself (which closes the popup). Ctrl with another letter, Left, Right, Delete and Insert do nothing, so they cannot change the field underneath. Shift, Ctrl, Alt, the Windows keys, the lock keys, Alt+Tab, Win+anything, Ctrl+Esc, F-keys and media keys go through to Windows and the app. Alt+F4 closes the popup and not the app. Repeats of keys held when the popup opened (the V of the shortcut) are dropped; a key the popup took stays away from the app until it is let go, so a held Enter does not type newlines after the paste.
- **The hook exists only while the popup is open,** plus up to 1.5 s for keys still held after a pick, and runs on a thread of its own: Windows removes a low-level hook that is slow to answer, which a busy UI thread could cause.
- **Search.** The search field is read-only and shows what was typed; the popup hands the text to the model itself, because a read-only `TextBox` did not report the change.
- **Mouse.** Clicks on the popup work without activating it: the search field, tabs and rows never take the focus (`AllowFocusOnInteraction="False"`), and the pin menu opens inside the popup without taking the focus (`FlyoutShowMode.Transient`, `ShouldConstrainToRootBounds`). A mouse hook reports a button press outside Clipo's windows; the popup closes and the click goes on to where it was aimed. Another window coming to the front (Alt+Tab, Start) also closes it.
- **Tray icon.** A click on the tray icon puts the taskbar in front; Clipo hands the front straight back to the app window the user was working in (`ForegroundTracker.AppWindowInFront()`) and opens the popup over it.
- **The desktop is a paste target.** `Progman` and `WorkerW` count as app windows although the desktop is a tool window (`WS_EX_TOOLWINDOW`), so a pick over the desktop pastes there.
- **Images into folders.** When an image is picked while the window to paste into shows a folder (Explorer, the desktop, or a window holding a `SHELLDLL_DefView`, such as an Open dialog), Clipo also writes the image to a file in `%TEMP%\Clipo`, named like Windows names screenshots (`Image 2026-11-01 141523.png`, translated), and puts it on the clipboard as `CF_HDROP` with `Preferred DropEffect` copy, beside the PNG and the bitmap. Only the last such file is kept; the folder is emptied when Clipo starts and quits. A packaged Clipo's writes under `%LOCALAPPDATA%` are redirected into its package, so the clipboard gets the file's real path (`GetFinalPathNameByHandle`).

**Why.**
- Decision 0016 activated the popup because Windows has no window that takes typing without being activated. Activation takes the focus from the field the user is in: the caret and the selection go, some fields close their suggestions or end an edit, and the focus has to be handed back, which Windows does not always allow. The user asked for the macOS behaviour: work in the popup while the field keeps the focus.
- A keyboard hook is how a window that is never activated gets keys. It is installed only while the popup is open, so Clipo sees no typing at any other time.
- Explorer and the desktop paste files, not pictures: with only `PNG` and `CF_DIB` on the clipboard, Ctrl+V in a folder does nothing, which is how a screenshot picked over a folder behaved. Adding the file only when the target shows a folder leaves other apps as they were: some prefer a file to a picture (Excel or OneNote would insert an attachment), and the history stays out of the temporary folder unless the user pastes into a folder.

**Checks.** A temporary harness drove the real Clipo, built from this change, on a hosted Windows Server 2025 runner with real input (Notepad, the tray icon, an Explorer folder and the desktop), with Paste After Choosing on. All 35 checks passed:
- Ctrl+Shift+V over Notepad: Notepad stayed in front and its edit box kept the keyboard focus; typed letters went into the popup's search and none reached Notepad; the search filtered the rows; Enter pasted the pick into Notepad.
- A click on a tab, a row and the pin menu (right-click, then Pin) worked with Notepad in front and its caret kept throughout. A thread sampling the window in front every millisecond for the whole run never saw a Clipo window there. The first click on the popup after Clipo starts makes WinUI move Clipo's own focus to its content, and Windows reports a foreground event for that, but the window in front, Notepad's active window, its focus and its caret did not change.
- A click in Notepad closed the popup and moved the caret as usual; Esc closed it and typing reached Notepad again.
- The tray icon, clicked in the hidden-icons flyout, opened the popup with Notepad back in front and its edit box focused; Enter pasted into Notepad.
- With only a bitmap on the clipboard, Ctrl+V in an Explorer folder created nothing (the reported bug). An image picked over the folder pasted as `Image <date> <time>.png`; picked over the desktop, it pasted there. The clipboard then held `PNG`, `CF_DIB`, `CF_HDROP` and `Preferred DropEffect`.

**Consequences.**
- The search field shows the search without a caret; there is no moving inside it, no selecting and no pasting into it.
- Typing that goes through an input method editor (Chinese, Japanese, Korean) reaches the popup as plain key characters, not composed text.
- Windows does not run a hook of a normal app for keys meant for a window running as administrator. Over such a window the popup works with the mouse only, as auto-paste already did not work there (decision 0016).
- Screen readers are told about the selected row as before, but the focus stays in the app underneath.
- An image picked over a folder leaves its decrypted file in `%TEMP%\Clipo` until the next such pick or until Clipo quits; pasted after Clipo quit, the file is gone and Explorer says so.
